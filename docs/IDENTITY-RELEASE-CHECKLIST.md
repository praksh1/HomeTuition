# Private identity verification release gate

Local implementation is not permission to turn collection on. No real citizenship documents are used in automated tests.

## Configuration (separate from ordinary uploads)

- `IDENTITY_COLLECTION_ENABLED`: defaults off. Opens private submissions only when cleanup health is confirmed.
- `IDENTITY_ENFORCEMENT_ENABLED`: defaults off. Applies only to teacher publication and acceptance of new bookings; students may book without an identity submission. Pausing uploads must not silently disable the teacher requirement.
- `IDENTITY_RETENTION_ENABLED`: defaults off. Starts the bounded cleanup scheduler; keep it running when collection is paused.
- `IDENTITY_REVIEWER_USER_IDS`: explicit comma-separated operator account IDs; fresh admin and operator-password checks still apply.
- `IDENTITY_R2_BUCKET`, `IDENTITY_R2_ACCESS_KEY_ID`, `IDENTITY_R2_SECRET_ACCESS_KEY`: dedicated non-public bucket and bucket-scoped credentials, never the ordinary attachment bucket. No public domain or public-development URL.
- `IDENTITY_ENCRYPTION_KEY_V1`: dedicated 32-byte key encoded as 64 hex characters, stored only in the secret manager. Never substitute another application secret. Encryption-key loss prevents recovery; document a protected backup/rotation procedure before activation.
- `ACCOUNT_CLOSURE_REQUESTS_ENABLED`, `ACCOUNT_CLOSURE_MEDIA_ENABLED`, `ACCOUNT_CLOSURE_COMPLETION_ENABLED`: separate default-off rollout controls. Requesting closure never stops existing access. Completion additionally requires an active media worker heartbeat and no failed pending disconnections. Do not enable completion for mixed Daily/native deployments: this release implements strict revocation for LiveKit Cloud only.
- The existing `R2_ACCOUNT_ID` / HTTPS `R2_ENDPOINT` identifies the storage service. No identity keys or values belong in source control.

## What is implemented locally

Private two-stage encrypted upload, safe account status, restricted audited operator review, inline image and paged-PDF preview, deliberate manual decision, generic durable status notification, teacher Profile entry points, teacher publication/new-booking gates, and a transaction-backed cleanup batch with a persisted lease/checkpoint. Student/parent citizenship collection is retained in the codebase for possible future use but is not exposed or required in the current product.

Restricted case-linked preservation holds now support explicit placement, 90-day review and release, with version checks, private audit receipts and no automatic expiry. Operator reads lock the record against concurrent retention deletion. Legacy citizenship references are quarantined from general attachment signing/reuse and ordinary credential screens; existing objects have not been migrated or deleted. Legacy standalone publication and monthly joining preserve account-readiness checks, while teacher identity approval is enforced at publication and booking acceptance. These changes remain local and require database/storage integration verification.

DOB is BS-first where the private teacher verification form asks for it; AD is optional input/reference. The API keeps a canonical AD **civil date**, not a UTC timestamp; calendar switching must preserve that date. The dormant parent-document form keeps parent DOB separate from student DOB, but must not be exposed or required unless the owner later approves restoring student verification.

Cleanup runs in small batches, retries failed objects without marking them deleted, and uses row locks against concurrent hold/deletion operations. A completed scan is due again after 24 hours; failed batches retry after five minutes. Process restarts resume the persisted cursor. Cleanup continues independently of the collection flag. New uploads fail closed if a completed cycle cannot be confirmed within 48 hours. This is an operator health indicator, not an external outage-alert service.
