# Working on this project

Orientation for anyone — human or AI — picking this up fresh.

---

## What it is

A live teaching platform for Nepal. Teachers run scheduled classes; students find them, book
and pay, then join a video call with a shared whiteboard. Works on the web, iOS and Android.

**The whiteboard is the selling point.** It is not a side feature — it is the reason someone
would choose this over a plain video call, and it should be treated as the product.

Anyone can teach any subject here. The founder's words: a teacher might be "a 15 year old or an
80 year old", and many will not own a laptop. Design for a cheap Android phone on a poor
connection, not for a developer's laptop.

## Who you are working with

The owner is a **non-technical founder**. The app was originally generated by Replit AI and has
been substantially rewritten since.

This shapes how to communicate:

- Explain *why* something broke and what it means for users, not just what changed.
- Do not hand over commands without saying which directory to run them in. This has caused real
  frustration — see the Windows section below.
- Verify claims before making them. "It should work now" without evidence is not acceptable
  here; several past bugs were declared fixed and were not.
- When something cannot be done, say so plainly and give the honest cost, rather than
  half-building it.

## Architecture

pnpm workspaces monorepo. Node 22+, pnpm 11.

```
artifacts/api-server/   Express 5 + Drizzle ORM + WebSocket hub    → Railway
artifacts/sikshya/      Expo SDK 54 / React Native 0.81 / expo-router 6  → Cloudflare Workers
lib/db/                 Drizzle schema, shared                     → Neon Postgres
```

The app builds to **web, iOS and Android from one codebase**. Metro resolves `.web.tsx` before
`.tsx`, which is how platform-specific implementations are split (see `DailyEmbed`,
`SmartBoard`).

**Video** is Daily.co: the Prebuilt iframe on web, the native SDK on iOS/Android. Teachers get
an owner token so they can moderate.

**The classroom WebSocket** (`artifacts/api-server/src/ws/classroomHub.ts`) carries presence,
chat, session status and the whiteboard. Board state is in memory, so a server restart loses a
live board — persisting it is a known gap.

### Two rules that must not be broken

**1. Access control lives in one place.** `artifacts/api-server/src/lib/membership.ts` answers
"may this user be in this class?" and both doors — the video room route and the WebSocket —
call it. They used to disagree: the socket checked membership while the room route only checked
that you were logged in, so an unenrolled student saw the "not enrolled" banner while the
teacher's video played behind it. Never re-implement this check somewhere else.

**2. Booking is atomic, and there is no "pending" payment.** `POST /sessions/:id/book` runs one
transaction that either commits an enrolment already marked paid, or writes nothing at all. The
old two-step flow (enrol, then confirm payment) left students holding classes they believed
they had bought but could not enter. Do not reintroduce a state between "not booked" and
"booked and paid".

Payments run in **gateway** mode when a provider is configured and **simulated** mode when none
is, and the mode follows from what exists in the environment rather than a flag. Configuring a
real provider permanently disables simulated mode — that self-tightening is deliberate, so real
payments cannot be switched on while the free door is still open. See `lib/payments.ts`.

## Running it

Full instructions: `LOCAL_SETUP.md`. Deploying: `DEPLOY.md`. Whiteboard design and roadmap:
`WHITEBOARD.md`. Bug log: `ISSUES.md`.

From the repo root:

```
pnpm run dev:api      # port 8080
pnpm run dev:app      # Expo web, port 8081
pnpm run typecheck    # all four packages — run this before claiming anything works
pnpm run db:push
pnpm run seed
```

**Secrets are not in the repo.** `.env` at the root holds `DATABASE_URL`, `SESSION_SECRET`,
`PORT`, `NODE_ENV`; `artifacts/sikshya/.env` holds the app's. Both are gitignored. A fresh
clone will not run until they exist — ask the owner for them rather than guessing.

## Deploying

**The API redeploys itself** when you push (Railway watches the repo). **The web app now does
too**, via `.github/workflows/deploy-web.yml` — a push to `main` runs the checks and deploys.
That workflow needs the `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` repository secrets;
without them everything is still checked and the deploy step simply says so rather than
failing.

The manual path still works if the workflow is ever unavailable:

```
pnpm --filter @workspace/sikshya run build
npx wrangler deploy
```

`EXPO_PUBLIC_API_URL` is baked in at build time, not read at run time — and Metro caches that
substitution without the value in its cache key, so changing the API address and rebuilding
used to succeed while still shipping the old one. `scripts/build.js` now clears the bundler
cache when the address changes and fails the build if the result does not contain it. See
`.agents/memory/metro-cache-stale-api-url.md`.

## Windows traps

The owner develops on Windows. Every one of these has cost real time.

**The repo root is a nested folder of the same name:** `C:\Projects\Paathshala\Paathshala`.
Running from the parent gives `ERR_PNPM_NO_PKG_MANIFEST`. Always say the full path.

**PowerShell blocks `.ps1` scripts**, and Node ships its tools as PowerShell scripts. So
`pnpm`, `npx` and `npm` all fail with `UnauthorizedAccess` / "running scripts is disabled on
this system". **Use `pnpm.cmd`, `npx.cmd`, `npm.cmd`.** This applies to every command handed
over.

**`android/local.properties` needs forward slashes** —
`sdk.dir=C:/Users/missk/AppData/Local/Android/Sdk`. It is a Java properties file, so
backslashes are escapes, and Gradle fails with a confusing "filename, directory name, or volume
label syntax is incorrect".

**Never set `nodeLinker: hoisted`.** It was tried to shorten paths and had to be reverted:
flattening the tree collapses each package's private dependency copies, which conflicts with
the exact `@react-navigation/native` pin and leaves React null inside expo-router — the app dies
at startup on *both* web and native with "Invalid hook call".

**Android builds locally, no paid cloud account needed.** From `artifacts/sikshya`:
`pnpm exec expo prebuild -p android --no-install`, then `cd android && ./gradlew
:app:assembleDebug`. `android/` and `ios/` are generated and gitignored — never hand-edit them.

**Package versions must match Expo SDK 54.** Installing SDK 56 packages produces a
`ClassNotFoundException` on device, which looks like a native bug and is not.

## Current state

Working and verified: booking and payment, the 5-minute early-join lobby, in-app chat on web
and native, unread message counts, and the whiteboard on Excalidraw with object manipulation,
an infinite canvas, shared images and PDFs as real board objects, and a scene that stays in
step with every student — including erasures and the teacher's viewport.

Notifications are real now, and were not before: what users saw was six samples the app
invented in local storage on first run. A signed-in app holds one WebSocket to the server
(`ws/userHub.ts`, separate from the classroom socket) and hears about messages, new followers
and classes going live, subject to per-user preferences stored server-side. See
`ISSUES.md` → E10.

Known gaps, in rough priority order:

1. **Email cannot be sent until a provider is configured.** `lib/mailer.ts` is written and the
   preference switches exist; without `RESEND_API_KEY` and `EMAIL_FROM` the app says so plainly
   rather than pretending. Same self-describing pattern as payments.
2. **WebView board performance on cheap Android is untested.** This matters more than it
   sounds, given the target market.
3. **Board state is not persisted** — a server restart loses a live lesson.
4. **Shape recognition is built but not connected.** `components/recognition/` works; its only
   caller was the SVG surface Excalidraw replaced, so nothing reaches it today. Re-wiring means
   catching Excalidraw's freehand commit — `WHITEBOARD.md` step 8.
5. **Handwriting-to-text is not built.** On-device OCR was tried and withdrawn: Tesseract reads
   printed text, and on handwriting a clearly drawn "B" came back "L". Doing it properly needs
   ML Kit (free, native only) or MyScript (paid). `WHITEBOARD.md` section 4 lays out the
   options honestly.
6. **A PDF picked on a phone opens locally, not on the board.** The picker hands back a
   `file://` URI with no bytes to share; the app says so rather than failing silently.
7. **No Bikram Sambat date picker** — Nepali users see Gregorian dates only.
8. **The app calls itself "Guru" in places** and Sikshya/HomeTuition in others.

## Testing expectations

The owner has asked for changes to be tested at scale, not spot-checked. Past work was verified
with 100+ iteration lifecycle runs, concurrency runs with nine simultaneous actors, and targeted
suites for access control, payments and board sync. Scripts of this kind are worth writing
before declaring a fix done.

Be especially careful with claims about fixes: several were previously reported as fixed while
still broken, and the owner caught them. Verify against a running server.
