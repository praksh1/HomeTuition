- [The design system, and the check that keeps it real](../../DESIGN.md) — agreed with the owner 27 Aug 2026. **Crimson `#C41E3A` is the brand and a LIVE class only, never a button; royal blue `#123C8C` is every action.** Before it, `primary` was crimson and `destructive` was red, so the button taking a student's money and the one cancelling their class were both red. Destructive is a burnt rust `#9A3412` (the obvious `#B3261E` measures 13° in hue from the brand crimson — the same red to a human) and is **never a filled button**. Nine type steps replace eighteen ad hoc sizes; `numeric` (tabular figures) goes on all money and clocks; Inter has no Devanagari so `family()` splits web from native. **Dark mode is deliberately absent — the owner's decision, do not add one without asking.** `constants/colors.ts` had been bypassed 468 times by hex in screens, so `lint:design` runs in CI as a **ratchet**: a per-file baseline that may go down and never up.
- [Every screen the app has, invents at least one number](../backlog/ui-upgrade-progress.md) — found while converting screens to the design system, and now the most valuable thing to look for. `sessionsThisMonth` and `monthlyEarnings` are written once to zero at registration and never again, so dashboards reported "0/10 classes" and "NPR 0k earned" to every teacher forever. The subscription screen invented three payments and promised session recording that exists nowhere. Discover labelled every teacher "Available" from `is_online`, which no screen writes, and had a filter on it that always matched nobody. **The test:** grep the column in `artifacts/api-server/src/` for a write that is not `auth.ts`; if registration is the only writer, the column is dead and the UI is lying. **Never a fabricated zero** — especially about money, where it is indistinguishable from a real answer.
